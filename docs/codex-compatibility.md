# Совместимость с обновлениями Codex

На 10 сентября 2026 года установленный ChatGPT/Codex имеет версию
`26.903.61454 (8378)`. Старый адаптер допускал только `26.721.41059 (5848)`
и искал файл `codex-micro-service-*.js`. В новой сборке сервис находится в
`service-BuBDjGBu.js`. Контракты экспорта сервиса и используемые renderer
markers сохранены. 10 сентября выполнен opt-in live E2E: handshake,
runtime capabilities, навигация, команды composer, вставки, PTT, Stop,
прокрутка и штатное закрытие прошли без ошибок. Тест использовал fake HID
и отдельный неотправленный черновик. Физические клавиши и LED он не проверяет.

Похожий [контроллер Codex Micro Phone](https://github.com/maxxspotter/codex-micro-app)
также документирует поломки внутренних адаптеров при обновлении Codex.
[Issue 34099](https://github.com/openai/codex/issues/34099) описывает отключения
настоящего Micro на macOS, но не доказывает причину проблемы Nostromo.
Базовые действия перечислены в [официальной справке команд](https://learn.chatgpt.com/docs/reference/commands).

## Поведение приложения

Полный режим использует приватный мост и включается только после проверки
версии, build, необходимых модулей и runtime capabilities. Общий manifest
находится в `Sources/NostromoCodexApp/Resources/codex-compatibility.json`.
`verified: false` означает подготовленный кандидат, а не разрешение запуска.
В списке разрешены пары `26.721.41059 (5848)`, `26.721.81911 (5973)`
и `26.903.61454 (8378)`. Swift и preload читают один manifest,
он упаковывается вместе с приложением.

При потере полного подключения базовый режим предлагает новую задачу,
предыдущую/следующую задачу, боковую панель и настройки. Используются точные
пункты системного меню Codex на русском/английском после активации приложения.
Переназначенные shortcut и клавиатурная раскладка не меняют выбранный пункт.
Нужен Accessibility. Отсутствующий, выключенный или неоднозначный пункт
ничего не выполняет. Остальные специальные действия недоступны; обычные
назначения клавиш и переключение профилей сохраняются.

Смена установленного bundle проверяется каждые две секунды. Замена отменяет
активный ввод и устаревшие capabilities. Для удержанных кнопок требуется
отпускание. Уже отправленная команда никогда не повторяется через резерв.
Обновление не вызывает принудительного перезапуска Codex. Если новая версия
запущена без preload, полное подключение требует явного перезапуска через
Connection; перед закрытием приложения проверяется совместимость.
В live-проверке сборке 8378 потребовалось 17 секунд для штатного закрытия.
Nostromo ждёт до 30 секунд и не запускает второй экземпляр, пока первый
остаётся работающим. Принудительное завершение не применяется.

## Проверка новой сборки

1. Выполнить `node scripts/inspect-codex.cjs`. Это чтение Info.plist/ASAR,
   без загрузки кода Codex, запуска приложения или доступа к HID. Статус
   `candidate-needs-live-test` не означает подтверждённую совместимость.
2. Проверить изменения export/API сервиса и используемых renderer actions.
   Поиск обязан находить ровно один модуль. Добавить версию/build как
   `verified: false`, если требуется новый кандидат.
3. Запустить Swift regressions, `node Tests/preload-unit.cjs` и
   `node Tests/preload-smoke.cjs`. Нельзя расширять scoped hooks или обходить
   отсутствующие API ради прохождения проверки.
4. Только после явного разрешения пользователя выполнить opt-in live E2E
   с `NOSTROMO_LIVE_E2E=1`. Он перезапускает Codex и использует fake HID;
   реальное устройство ему не нужно. Тест допускает только запись кандидата
   из manifest и включает override в своей временной конфигурации.
5. После успешной live-проверки пометить конкретную пару version/build
   `verified: true`, зафиксировать результаты и выполнить полный runner
   `./scripts/deep-test.sh --full --hardware-inventory` в разрешённой среде.
   HID/LED и физическую матрицу проверять отдельно.

Совместимость со всеми будущими приватными API не гарантируется. Резервный
режим уменьшает последствия обновлений; новые полные адаптеры по-прежнему
требуют проверки. Исходный upstream `scottfowler/codex-midi` при исследовании
возвращал 404; готового обновления библиотеки оттуда подтвердить не удалось.
